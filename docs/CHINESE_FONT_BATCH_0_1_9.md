# 0.1.9 Build17：按用户校对表批量替换字库

- ROM 标准 BIN SHA256：`e70f0a92c205ea432080cc48c18d1d43b7fc4d45464ed7fb218b119096e7cdd9`。原 ROM 文件不修改。
- 用户上传 974 字码前四列；其中 **355 个“需替换”** 字码对应的 16×16 / 32 bytes 字模用同 0.1.8“刘备”相同的细笔画明体生成。
- 619 个“无需替换”字模完全不改。
- 启动时 `bawang_font_overlay_apply()` 对全部 355 项在写入前执行双版本字节检查；原版 ROM 先完成整体 SHA256 验证，overlay 仅修改内存 `g_rom`。
- 繁体与简体切换仍使用已有的 `bawang_core_set_simplified()` API。ROM/SRAM 持久化均未改。
- 字符号有多字义（如“著”“乾”“幹”）时，本轮严格执行用户确认的字形映射，语义精修应在具体文本位置实施，不得改动整个字库槽位以修订一句话。
- 此补丁**没有直接替换游戏台词**。文本审校见交付包内的 CSV/XLSX。
- 现存 VDP 图块可能不会因为 g_rom 的字模修改就立刻更新，重新打开相应画面验证。
- 本地 C 动态库校验：全部 355 项可逆，未标记的字模不变；损坏的输入拒绝且不发生部分写入。
- 未完成 iPhone 真机或 Xcode 编译，请不要将此处的测试当成 IPA 验收。
