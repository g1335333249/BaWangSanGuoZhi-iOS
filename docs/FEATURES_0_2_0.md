# 霸王三国志 0.2.0 Build 18 · 快照、触摸、画面平滑试验版

## 变更范围

- 游戏运行中：可以创建多个互不覆盖的版本快照，包含名称、日期、画面缩略图和实际完成的帧号；使用上游 `genesis_rb_save/load` 保存完整 CPU/显存/Z80/音频/原生 fiber 执行状态，同一进程内对最近 3 个内存快照优先瞬间恢复（避免缓存占用过多 iPhone 内存）；其他槽位走完整重放。
- 重新打开 App：**不把含宿主指针的原生栈写入跨进程存档**。文件保存启动时的有效 64 KiB SRAM、每帧手柄实际输入（含语言模式变更）和完整客体状态指纹；重新启动模拟核心、逐帧确定性重放，并在指纹完全匹配后允许继续操作。不同版本仍允许尝试校验，错误、断电、取消或新版本语义不一致时绝不把错误状态写入现有 SRAM。
- 重要限制：长回合进度的首次冷恢复可能要等待数分钟，且 **尚无 iOS / 真机确定性回放验收**。冷恢复是一键操作但不是模拟器那种跨重启毫秒级读盘，UI 显示进度且可取消。在真实环境严格验收前请保留原版游戏存档作为兜底。
- 点击画面：中央内容真实触摸坐标转换为 256/320×224 游戏坐标。可直接点顶部四个栏目（需要能识别粉红选中栏与蓝色普通栏），其余区域轻点= C 确认、滑动=方向。暂未实现任意地图城市/武将名单的坐标精准点击，仍保留全部虚拟按键；不会改写游戏 RAM。
- 显示：保留原版 nearest，新增 bilinear 和对高对比笔画倾向 nearest 的平滑模式。底层信息依然是 256/320×224，不是 AI 高清重绘。
- SRAM：普通原版 SRAM 继续按旧路径自动保存。恢复快照前使用新的游戏核心和临时 SRAM，只有完全通过指纹验证才备份当前 SRAM 至 `bawang.before-restore.srm` 并写回恢复状态。

## 严格验收清单

1. iOS Simulator / iphoneos ARM64 Release **实际编译**，查看 ObjC bridge 是否完整链接 `genesis_rb_` 系列。
2. 189 年刘备、194 年袁术分别选择已知场景，保存快照 A、B，进度发生变化后载入 A 再载入 B，验证年份/月、金钱、指令菜单、VDP 画面、SRAM 一致。
3. 强制结束 App 后冷启动从列表选择 A、B，等待回放进度完成；验证完整指纹一致、输入可继续。故意损坏 `.bws`，必须拒绝恢复且旧 SRAM 不变。
4. 回放运行到很长的场景（例如 20000 帧、5 万帧），测量载入耗时和内存占用。给用户清楚的进度及取消能力。
5. 测试旧 App 的 `bawang.srm`、盖装升级、同一签名 ID，确认不会清掉旧存档。测试切换繁简语言后创建快照与冷恢复。
6. 真机轻点四个顶部栏目以及普通菜单确认、上下左右滑动、虚拟按钮多点触摸，避免互相抢夺事件。
7. `BawangVideoFilter` 0/1/2 三档对人物、汉字、地图、边缘线的表现；双线性文字模糊是预期差异，不可宣称“真正高清”。

## 未来真正“秒级跨重启恢复”的架构

现有 fiber_snapshot_load 硬性要求同一 fiber 栈地址，直接写入磁盘并下次读回会失效。若希望不回放百万帧便直接回到旧界面，需要游戏特定的稳定续跑 PC/模式适配（`GameSpec.state_save/load` / `save_resume_pc`）或对栈和指针全面地址无关的再定位存档。应为独立里程碑并进行长时间原生与参考解释器验证。
